## 1. 执政支持率：放哪里，怎么算

### 1.1 事实

普拉博沃满意度 **81.2%（2025-11）→ 51.1%（2026-07）**，9 个月降 30.1 个百分点。
这大概是本期最强的社会稳定性信号，而当前五支柱**没有任何 driver 承接它**。

### 1.2 放「社会与街头」，不放「制度与政策」

社会支柱的问句是「老百姓承受力到临界了吗？愤怒在酝酿还是已上街？」——支持率正是
**怨气到达街头之前的存量读数**，位置在「消费者信心」（经济情绪）与「网络政治情绪」
（线上情绪）之间，是三者中唯一覆盖**一般人口**的。

放制度支柱是错配：制度支柱测的是规则可预期性，而一个高支持率的政府完全可以同时
拆解司法独立——这正是当下的基准情形。把支持率放进制度会让该支柱在制度侵蚀时反而
被民意托住。

### 1.3 与「网络政治情绪」的重复计分问题

两者都测政治情绪，但**测的是不同人群**：民调覆盖一般人口，社媒反对率覆盖线上活跃者。
线上永远比大众更极端——所以**两者的差本身是信号**，与本框架已在用的「民媒差」同构：

```
民意-网络差 = 民调不满意率 − 社媒反对率
差值大 → 愤怒集中在线上活跃层，尚未扩散
差值收敛 → 线上情绪已成为大众情绪，动员门槛显著下降
```

建议：**不降低网络政治情绪的权重**，而是把「差值收敛」作为社会支柱的 `pillarAdj`
触发条件（收敛至 10pp 以内时 −3），这样既不重复计分，又抓住了扩散这个真正的相变点。

### 1.4 拟议 driver

```
name: 执政支持率            type: quant     weight: 0.20
metric: 总统满意度（全国民调，取最近一期）
formula: ≥70%=75; 55–70%=60; 45–55%=45; 35–45%=30; <35%=15
         另加变化率扣分（可核查）: 12个月内降幅 >20pp 再 −10
当前: 51.1%（2026-07）→ 45 档；12个月降 30.1pp → −10 → 35
```

**变化率扣分是关键设计**。50% 的支持率在稳态下不算危险；**从 81% 掉到 51%** 是另一回事
——它说明政治联盟的兑付能力正在快速消失，这与本框架「盯变化率不只盯水位」的原则一致。

**数据源**：LSI / Indikator / SMRC 等定期民调。**风险**：各家口径与抽样不同，需固定
主源并在换源时留痕；选举临近时民调本身会被政治化。建议主源固定，异常值需二源印证。

### 1.5 权重再分配（社会支柱）

| driver | 现权重 | 拟议 | 说明 |
|---|---:|---:|---|
| 消费者信心 | 0.20 | 0.15 | 与新的购买力项部分重叠，降权 |
| 劳动力市场压力 | 0.20 | 0.15 | 同上 |
| 网络政治情绪 | 0.25 | 0.25 | 不动（见 1.3） |
| ~~燃油补贴红线~~ → 必需品实际购买力 | 0.20 | 0.15 | 见第 2 节 |
| 动员性质 | 0.15 | 0.10 | 唯一保留的纯序数项 |
| **执政支持率（新）** | — | **0.20** | |

硬数据占比由 60% 升至 **90%**（仅「动员性质」为序数）。

## 2. 「燃油补贴红线」→「必需品实际购买力」

### 2.1 现有口径的问题

所有者的判断成立：把燃油单列为一个占 20% 权重的因子，等于假定燃油是唯一的必需支出
冲击源。实际上食品与住房对底层可支配收入的挤压往往更大，而现有档位（「非补贴油大涨
32%、补贴油守住」）是**事件式描述**，不是可持续更新的度量。

### 2.2 拟议替代

```
name: 必需品实际购买力      type: quant     weight: 0.15
metric: 名义最低工资同比 − 必需品CPI同比
        必需品CPI = 食品/饮料 + 住房水电燃料 + 交通 三类加权
formula: ≥+3pp=70; 0~+3pp=55; −3~0pp=42; −6~−3pp=30; <−6pp=18
```

**为什么这个可行**：三类分项 CPI 是 BPS **月频**发布，UMP 年度公布（阶跃函数，可接受）。
交通分项已包含燃油，所以旧口径被完整吸收而非丢弃。

**诚实边界**：UMP 是法定最低工资，不等于实际收入中位数；非正规部门（印尼就业的多数）
不受 UMP 覆盖。这是代理变量，需在 `sources` 里标为「判断」而非「事实」。更好的做法是
接 BPS 实际工资指数，但其发布频率更低、修订更频繁——建议先用 UMP 版本起步，
标注为待升级。

## 3. 「政策方差」与「法治与执法工具化」

### 3.1 政策方差：不同意「抽象」的判断

它已经是**可审计计数**，不是主观打分：

```
0次=80; 1次=60; 2次=45; ≥3次=30
清单: ①B50生物柴油(1/14推迟→3/31强制→7/9发布)
      ②IIFC/PFII(4/8"选址未定"→7/21<1月仓促立法,73条)
      ③DSI出口管制(2027→提前至2026-09，品类扩至全部大宗)
```

任何人拿这三条去核，都能得到同一个分数。**真正的缺陷是入选标准没有写明**——
「什么算重大政策骤变」目前靠判断。

建议补上明文标准（三条全满足才计入）：
1. 有正式文件/法规两端（原立场与新立场各有可引用出处）；
2. 方向反转或时间表提前 ≥6 个月；
3. 影响面达到行业级或以上。

这样分数仍是计数，可复现性由标准而非人保证。**不建议删除或替换。**

### 3.2 法治与执法工具化：反对用支持率替换

这是**构念错配**。支持率测的是民众是否满意，法治测的是权力是否受约束。一个总统可以
同时享有高支持率并拆解司法独立——这恰恰是本项目当前判断的基准情形。用支持率替换它，
会让指数在「民粹式威权巩固」这一最危险的路径上**变成瞎子**。

它确实软，但方向应是**换硬指标，不是换构念**。候选：

| 候选 | 可得性 | 评价 |
|---|---|---|
| WJP 法治指数 | 年度 | 权威但滞后一年，只能作锚不能跟踪 |
| V-Dem 司法约束指标 | 年度 | 同上 |
| **执法不对称比** | 需自建台账 | 反对派人物 vs 执政派人物被立案数之比，可从日频事件池累积 |

**建议**：保留该 driver，但把评分依据从整体判断改为**执法不对称比**——这正好复用已有的
日频事件池（`daily-events/*.jsonl` 已按类型记录「司法/执法工具化」事件）。攒 8–12 周后
即可用计数替代序数。这是把主观项转硬的可行路径，且不需要新数据源。

## 4. 历史可比性：怎么处理才不毁掉趋势图

### 4.1 三个选项

| 方案 | 优点 | 致命问题 |
|---|---|---|
| (a) 回溯重算全序列 | 趋势连续，可读斜率 | 需要新 driver 的历史输入 |
| (b) 旧分carry over，新口径只往前用 | 省事 | **在序列中间制造断点**，而断点恰好落在你最想读的地方 |
| (c) 双序列并行，N 周后再接 | 最稳 | 图上两条线，可读性差；且最终仍要面对拼接 |

### 4.2 建议：(a) 回溯重算

理由有三：

1. **本项目已有先例且已验证可行**：v2→v3 时就是回溯重算的，`data.js` 里至今保留
   「v2 原值: 07-07=56/44/40/60/47」的注释。同样的做法照搬即可。
2. **框架的核心读法是「盯变化率不只盯水位」**。方案 (b) 会让 08-11 那周的跳变同时
   包含「真实变化」和「换尺子」两个成分，而这两者无法事后分离——等于把这个框架
   最有价值的部分毁掉。
3. **新 driver 的历史输入是可得的**：民调有 2025-11 与 2026-07 等历史点；必需品 CPI
   是 BPS 月频历史序列；UMP 是年度公布值。6 期回溯（07-07 起）完全可行。

### 4.3 执行纪律（必须遵守，否则回溯本身会变成造假）

- **回溯用的必须是当时可得的数据**，不能用后见之明。例如 07-07 那期只能用当时最近
  一期民调，不能用 07 月底的调查结果。
- 每期回溯值在 `data.js` 注释里保留改动前的原值，与 v2→v3 的做法一致。
- 回溯完成后**立即跑 `validate_repo.mjs`**，并把 v4 影子的 `v3Score` 同步。
- 回溯本身单独一个 PR，与「新增 driver」的 PR 分开——否则 diff 无法审阅。

### 4.4 一个必须提前接受的代价

回溯后，**历史综合分会变**。当前 6 期的综合分（44→43→43→43→43→42）在加入支持率
（07 月 51.1% → 35 分档）后大概率整体下移 2–4 分。这不是「局势比原来更糟」，而是
**换了尺子**——与 v3 制度支柱当年高于 v2 是同一类现象。必须在 `weeklyAnalysis` 和
文档里写明，否则三个月后没人记得这个跳变是口径造成的。

## 7. 实施记录（2026-08-04）

所有者逐条批准：①支持率入社会支柱、权重 0.20；②叠加变化率扣分；③主源固定 Indikator；
④燃油补贴换必需品实际购买力（档位经试算重新校准）；⑤法治项保留、改执法不对称比（延后）；
⑥回溯重算、前 2 期标近似；⑦接受口径迁移。

### 试算修正了提案里的两处判断

1. **原估「综合分整体下移 2–4 分」是错的。** 社会支柱只占综合 1/5、支持率只占社会 0.20，
   该 driver 对综合的影响上限就是 4%。实际位移在 ±1.0 以内。
2. **第一版档位会让改造失去意义。** `≥+3pp=70` 使购买力项的全期抬升正好抵消支持率的末期
   下拉，净效果是曲线平移而非变陡。重新校准后才达成预期。

所有者要求「先跑一遍再决策」，这两处都是靠试算才发现的。

### 实施后的六期序列

| 日期 | 可用民调 | 支持率分 | 社会 旧→新 | 等权综合 旧→新 |
|---|---|---:|---:|---|
| 2026-07-07 | 4月 68% | 60 | 59→56 | 47.6→47.0 |
| 2026-07-16 | 4月 68% | 60 | 55→56 | 44.0→44.2 |
| 2026-07-22 | 4月 68% | 60 | 55→56 | 43.4→43.6 |
| 2026-07-28 | 4月 68% | 60 | 55→56 | 43.4→43.6 |

7/22→8/4 的下行由 −1.4 扩大到 **−2.4**；全期跌幅仅多 0.2——**变化被集中到真正发生变化的
那几周，而不是整条线被压低**，这正是本次改造的目的。

数据置信版权重下方向一致、幅度略大（社会占 0.25 而非 0.20），末期约 −1.0。

### 回溯纪律的实际执行

- 07-28 及以前用 Indikator **4 月 68%**——7 月调查 7/29 才发布，那几期确实不知道。
  这不是缺陷，是如实反映当时的信息状态。
- 07-07 与 07-16 两期的其余 social driver 值为**近似**：`data.js` 的 weekly 只存支柱总分，
  driver 只存 `score`/`prev`（回看一步），V4 证据台账也只从 07-22 起。已在 `data.js`
  weekly 上方注释中标明。
- 各支柱 `prev` 已同步为回溯序列的上一期值，使看板「周变化」只反映真实变化，
  不把口径迁移混进去。本次一并修正了此前就已陈旧的 `fiscal`/`currency` 的 `prev`。

### 附带完成：漏检补正（与 v3.1 无关的第二类回溯）

所有者要求把两组历史重调放在同一个 PR 里解决。除 v3.1 口径迁移外，另修正两个
**事件记账时点错位**——它们此前被记在「发现它们的那一期」，而不是「证据公开可得的那一期」：
